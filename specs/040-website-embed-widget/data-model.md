# Data Model: Website Embed Widget

## Overview

The feature extends existing workspace-scoped public-chat capabilities with a new website-embed channel. To minimize new seams, the primary durable state lives on the existing `workspaces` record and reuse continues through existing conversation/message/public-session storage.

## Entities

### Website Embed Settings

**Represents**: Workspace-scoped operator configuration controlling whether website embed is available and how the launcher is presented.

**Proposed fields**:
- `websiteEmbedEnabled`: boolean
- `websiteEmbedToken`: string | null
- `websiteEmbedAllowedOrigins`: string[]
- `websiteEmbedLauncherLabel`: string
- `websiteEmbedLauncherIcon`: string
- `websiteEmbedLauncherPosition`: enum-like string (`bottom-right`, `bottom-left`)

**Validation rules**:
- `websiteEmbedToken` is generated by the server and is non-guessable.
- `websiteEmbedAllowedOrigins` must contain at least one valid origin when embed is enabled.
- Launcher label stays within a compact operator-facing length cap.
- Position is constrained to an approved finite set.

**Relationships**:
- Belongs to exactly one workspace.
- Drives installer snippet generation and embed launch authorization.

### Embed Session Grant

**Represents**: A short-lived authorization result issued to an approved browser launch so the hosted iframe can initialize without using long-lived privileged credentials.

**Proposed fields**:
- `workspaceId`
- `embedToken`
- `origin`
- `expiresAt`
- `issuedAt`
- `channel`: fixed as `website_embed`

**Validation rules**:
- Must only be issued when `websiteEmbedEnabled` is true.
- Must only be issued for an origin present in `websiteEmbedAllowedOrigins`.
- Expiration is intentionally short-lived.

**Relationships**:
- Derived from one workspace’s website-embed settings.
- Used only for iframe startup and public chat continuity bootstrap.

### Embedded Visitor Session

**Represents**: A browser-scoped public chat session launched from an approved embedded assistant.

**Proposed fields**:
- Existing anonymous/public session cookie value
- `workspaceId`
- `sourceChannel`: `website_embed`
- conversation linkage through existing conversations/messages

**Validation rules**:
- Session continuity is maintained via server-controlled cookies or equivalent browser-safe session state.
- Must never expose admin or workspace credentials to the host page.

**Relationships**:
- Belongs to one workspace.
- May own one or more conversations over time through the existing chat tables.

### Embed Launch Audit Event

**Represents**: A recorded settings or access decision relevant to website embed operations.

**Proposed fields**:
- `eventType`
- `workspaceId`
- `accountId`
- `eventStatus`
- metadata including origin, allow/deny reason, and launcher settings changes where relevant

**Validation rules**:
- Metadata must explain decisions without exposing secret token values.

**Relationships**:
- Reuses existing audit-event persistence.

## State Transitions

### Website Embed Settings

1. `disabled` -> `enabled`
   - Requires a generated `websiteEmbedToken`
   - Requires at least one approved origin
2. `enabled` -> `disabled`
   - Blocks new embed launches immediately
   - Existing conversations remain in history
3. `enabled` -> `enabled` with updated config
   - Allowed origins and launcher config update in place
   - New launches use the latest rules immediately

### Embed Session Grant

1. `requested`
2. `issued`
3. `expired`

Denied launches never become active sessions and should still produce audit or operator-visible diagnostics.

## Persistence Strategy

### Reused persistence

- `workspaces` remains the primary durable owner of general settings
- `conversations` and `messages` remain the durable owner of chat history
- `audit_events` remains the durable owner of operator-visible launch and settings diagnostics

### Additive persistence expected

- Add website-embed columns to `workspaces`
- Avoid introducing a new table unless implementation discovery shows a compelling need that cannot be satisfied by additive workspace fields

## Open Questions Resolved By Research

- Dedicated embed settings table is unnecessary for v1.
- A generalized public-access persistence model is unnecessary for v1.
- A dedicated embed token is preferred over reusing the anonymous public-link token so channel control remains independent.
