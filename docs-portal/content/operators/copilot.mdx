# Operator Copilot

Copilot helps you investigate an agent without leaving the dashboard. Ask why a
conversation received a particular answer, why retrieval did not run, or which
trace stage produced a refusal. Copilot reads the workspace data available to
your operator session and streams its findings as it works.

## Open the panel

The Copilot panel is available on every dashboard view. Choose **Copilot** in
the top bar, or press **Cmd/Ctrl+J**. The panel stays available while you move
between Activity, Agents, Knowledge Base, Eval, and Quality.

The panel keeps three useful pieces together:

- **Conversations** keeps saved Copilot threads. Select one to continue it, or
  choose **New conversation** for a separate investigation.
- **The thread** shows your question, the streamed answer, the activity behind
  the answer, and any entities Copilot read during the turn.
- **Current context** shows the dashboard view and the named agents,
  conversations, routines, eval cases, or documents currently rendered on the
  screen.

The full-page **Copilot** view uses the same thread and context. It is useful
when you want more room for the conversation list and context rail.

## Ask about what you see

The panel captures the dashboard context that is already on screen. A selected
conversation row, agent, routine, eval case, or trace stage can be included in
the next turn, with display names shown in the context rail.

To ask about a particular sentence, select the text in the dashboard. Choose
**Ask Copilot** beside the selection. Copilot opens with the text quoted in the
composer and sends it as selected context, limited to 2,000 characters.

When a turn reads a specific conversation, agent, or routine, the answer shows
a **Read during this turn** chip. Choose a chip to open the matching dashboard
surface. If the current screen has no display name for an entity, the chip uses
its id so the link remains useful.

On an empty thread, suggested questions adapt to the view and focused entity.
For example, a focused conversation offers to explain what happened in that
conversation.

## Review proposals

When Copilot identifies a configuration change, it can draft a proposal for a
directive or an agent setting. The proposal card names the target, summarizes
the change, and shows the current and proposed values before anything is
written. Expand **Show changes** to inspect the field-level diff.

Operators with `workspace.agents.manage` can choose **Apply** and confirm the
change. Copilot sends the confirmed proposal through the same guarded
management service used by the dashboard. Operators with read access can
review or dismiss a pending proposal; the Apply action is available only when
their session can manage agents.

Each proposal is checked against the target version captured while it was
drafted. If the target changed in the meantime, the card becomes **Stale** and
explains that the change was not applied. Ask Copilot to draft the change again
so the proposal reflects the current configuration. Applied proposals link to
the target entity, while failed proposals show the reason returned by the
management service.

## Follow a running turn

While Copilot works, activity lines show the UI-safe capability label and its
stage. For example, **Reading conversation trace — started** becomes
**completed** when that read finishes. After the turn completes, the timeline
collapses to a one-line summary; choose it to inspect the individual reads. A
failed activity stays visible so you can distinguish an incomplete
investigation from a successful one.

The answer carries a terminal outcome:

- **Completed** means the turn reached its normal end.
- **Budget exhausted** means Copilot returned its partial findings after its
  runtime budget ran out.
- **Turn failed** means the turn could not complete. Read the visible activity
  and error state before retrying. Choose **Retry** to send the same question
  again with the current page context.

Only one turn runs in a Copilot conversation at a time. The composer is
disabled while a turn is active, and a conversation that is already running
shows the same locked state when you open it.

## Manage conversations

Your Copilot conversations are separate from customer Activity, quality, and
history views. Return to Copilot to resume a saved thread. Use **Delete** in
the thread header and confirm to remove the selected conversation and its
messages.

Copilot is available to operators with `workspace.agents.read`. It uses the
dashboard session, so workspace API bearer tokens cannot start a Copilot turn.
When the workspace has no resolved LLM capability, Copilot shows a provider
setup state with a link to **Settings → Providers**.

## Common failure modes

- **The Copilot entry is missing** — your session does not hold
  `workspace.agents.read` for the active workspace.
- **Provider setup appears** — configure or select an LLM under **Settings →
  Providers**, then return to Copilot.
- **A turn remains locked** — another turn is still running in that
  conversation. Select a different Copilot conversation or wait for the
  running turn to finish.
- **A tool activity fails** — Copilot continues where it can and marks the
  affected turn honestly. The answer identifies the data it could not access.
- **A proposal is stale** — the target changed after Copilot drafted it. Ask
  Copilot to prepare the change again and review the updated diff.
