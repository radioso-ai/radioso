# Grounded answers

This page covers one capability: answers people can check. The rule it runs under is that if an answer matters, the system should be able to show what supported it, and it should fail honestly when that support is missing.

Answering is one of three things a Radioso agent does — it also acts and hands off, inside the rules you author. [Guided autonomy](/why-radioso/guided-autonomy) covers the wider picture.

## The product point of view

Many AI products optimize first for fluency. Radioso optimizes first for defensibility.

That changes the product in visible ways:

- retrieval behavior can be adjusted per agent because answer quality depends on the evidence path
- citations are part of the answer experience rather than a debugging extra
- unsupported claims should degrade honestly instead of sounding confident
- operators should be able to inspect why the system answered the way it did

## A simple example

Imagine a customer asks:

`Do you offer refunds after 30 days?`

There are two very different product behaviors:

1. A generic assistant gives a polished answer based on patterns it has seen elsewhere.
2. A grounded agent answers from your workspace documents, cites the supporting source, or says it does not have support for that claim.

Radioso is built for the second behavior.

## How Radioso gets there

<Steps>
### Retrieve evidence

The system searches workspace documents and applies system defaults plus any selected agent retrieval skill settings to gather the best candidate context.

### Build the answer with traceable support

The answer path keeps track of which chunks support which parts of the response.

### Present answers with citations

The presented answer keeps citation metadata connected to the retrieved chunks that support the response.
</Steps>

## Why this matters in practice

- support teams need answers they can stand behind
- customer-facing agents need to avoid inventing policy
- customers need a path back to the source of an important claim
- operators need to improve quality by inspecting retrieval behavior, not by guessing blindly

<Callout type="info" emoji="i">
  The key point is that grounded answers are not one isolated feature. They are the contract that ties retrieval, citations, and unsupported-answer handling together.
</Callout>

## What success looks like

- a user can ask a policy or product question and get an answer tied to workspace content
- citations point to the material that actually supports the claim
- unsupported questions degrade clearly instead of sounding authoritative
- operators can improve quality by adjusting ingestion and per-agent retrieval behavior rather than rewriting the whole system prompt
