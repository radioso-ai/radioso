# Data Residency

Radioso's own backend, database, and documents run wherever you deploy them. A handful of outside services sit behind that: a model provider for chat and embeddings, a voice vendor for calls, an email provider for outbound and inbound mail, product analytics, Slack, and Stripe. Each one decides where it processes the data you send it, and that's a separate question from where Radioso itself runs. This page lists each one, what it handles, and the setting — if there is one — that controls its region.

## OpenAI

The native `openai` provider backs chat, embeddings, and rerank. By default, platform-held OpenAI traffic goes to OpenAI's global API. Set `OPENAI_DATA_RESIDENCY=eu` or `OPENAI_DATA_RESIDENCY=us` on the backend, document worker, and crawler worker to send it to OpenAI's EU or US data-residency endpoint instead.

Getting OpenAI itself to process requests in-region takes its own setup, separate from this flag:

1. Apply for OpenAI's abuse-monitoring controls and sign its Modified Retention amendment.
2. Create a new OpenAI project with its region set to Europe (or United States) and issue an API key from it — an existing project can't change region after the fact.
3. Confirm every model you use, including the embedding model, is served in that region before you switch.
4. Set `OPENAI_DATA_RESIDENCY` and replace `OPENAI_API_KEY` with the new project's key together, then redeploy.

A workspace's own OpenAI key (Settings → Providers, bring-your-own-key) ignores `OPENAI_DATA_RESIDENCY` entirely. That key's project already picked its region when it was created, and sending a global-project key to a regional endpoint fails unless the organization is approved for one. `OPENAI_DATA_RESIDENCY` only ever reaches the platform-held key in `OPENAI_API_KEY`.

## Anthropic and Gemini

Claude and Gemini are reached only through a workspace's own API key — there's no platform-held key for either, and no region setting. The key's own project and provider account decide where its requests run.

## ElevenLabs (voice channel)

A voice runtime key is a workspace's own ElevenLabs account, set under Settings → Providers → Voice runtime keys. The agent's **Voice** card picks that account's **Data residency** — United States (the default), European Union, India, or Singapore — and it has to match whichever region the ElevenLabs account itself is provisioned for. EU residency needs an Enterprise ElevenLabs account; picking it on an account that isn't Enterprise reads like a wrong key, because the account's data only ever lives on its region's host.

## Resend (email)

Resend sends and receives mail for the email channel. `RESEND_CHANNEL_REGION` picks the region of the sending domain Resend provisions for the channel — `eu-west-1` for an EU deployment, `us-east-1` by default. It doesn't move Resend's own account data, delivery metadata, logs, or received message content, which Resend keeps in the United States regardless. If your deployment needs a safeguard for that transfer — standard contractual clauses, for example — put it in place separately; this setting doesn't provide one.

## PostHog

Product analytics and OTEL log export both go through `POSTHOG_HOST`. Point it at PostHog's EU ingestion host (`https://eu.i.posthog.com`) to keep analytics data in the EU, or its US host to keep it in the US.

## Slack and Stripe

The Slack and Stripe integrations each reach their provider's global, US-based API. Neither has a region setting.
