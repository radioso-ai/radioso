# Connectors and webhooks

Connectors link a workspace to external systems. The exact config shape depends on the connector type. The connector routes take a workspace token and answer on the host that issued it — see [Workspaces and tokens](/api/workspaces-and-tokens).

## How it works

1. List the connectors available to the workspace.
2. Read one connector's current detail.
3. Save connector-specific config.
4. Enable the connector when the config is ready.
5. Run a manual sync when the connector supports it.

Connector config is not one global schema. The body depends on the connector you are configuring, so the [API Reference](/api-reference) is the authoritative place for the exact shape.

Connector detail responses also include `syncState`. This shows whether a sync is queued or running, the latest backfill completion time, latest sync attempt, upstream modified cursor, count ingested by the last sync, and the operator-safe `lastError` from the latest failed sync. A successful sync clears `lastError`.

## Built-in connectors

Radioso ships with these connector types:

- `wordpress`: syncs any WordPress post type — pages, posts, and custom types such as WooCommerce products — into workspace documents. It supports push webhooks and optional manual sync.
- `whatsapp`: receives WhatsApp Business Cloud API messages, sends them through assistant chat, and replies through WhatsApp. It does not support manual sync.

For WordPress, each post is ingested from its rendered content. Set **Post types to sync** to the comma-separated list of types you want, such as `page,post,product`.

The companion plugin appends a facts block to the content it pushes. The block lists the post's public taxonomy terms and, on WooCommerce sites, the SKU, the price, the availability the shop is showing, and the visible product attributes — each labelled with the site's own wording, so a catalogue arrives in the language it was authored in. Prices carry the shop's tax and currency settings, and a variable product carries the range across its variations rather than a single figure.

Alongside the facts block, WooCommerce products carry their shop values as document metadata, so retrieval can filter and boost on them rather than only read them out. A product publishes `sku`, `price`, `currency`, `on_sale` and `stock_status`, plus `regular_price` and `sale_price` when the shop sets them, and `price_max` when a variable product's variations span a range. Prices are the display prices — the same figures the facts block quotes — while `stock_status` is WooCommerce's own value (`instock`, `outofstock`, `onbackorder`), so a rule written against it survives a change of shop language. Write a metadata rule against any of these keys under the retrieval skill's settings: `price` less than `20`, or `stock_status` equals `instock` as a hard filter. A change to one of these values re-indexes the document on its own, even when the post body is untouched.

Any site can publish its own values the same way. The webhook payload accepts a `post.fields` object of string, number and boolean values under keys matching `^[A-Za-z][A-Za-z0-9_]{0,63}$` — up to 32 per post — and Radioso stores them as document metadata under those keys. A key that collides with one Radioso derives, such as `author` or `dateFrom`, keeps Radioso's value.

Price and availability both move without anyone editing the post, through scheduled sales, imports, bulk edits and orders. The plugin re-pushes a product whenever WooCommerce saves it, flips its stock status, or recalculates a variable price range from its variations, so both stay current. Publishes and updates go out at the end of the request, which collapses the several hooks one save trips into a single push and lets it carry the state the request finished with. Deletes go out immediately, while the post still exists.

The author's display name is stored as document metadata (`author`) — drawn from the embedded author on REST sync and from the push payload on webhooks — and included in searchable and answer context, so assistants can find and identify an author even when WordPress omits the byline from the post body. On pages and posts this is the WordPress account that wrote the post. Catalogues that record the author of the work in a taxonomy set **Author taxonomy** in the plugin settings to that taxonomy, and Radioso stores those term names as the author instead. The publish date is stored the same way: the raw timestamp under `published_at` and its day under `dateFrom`, so posts are searchable by date and usable in date metadata rules. Existing documents pick up the author, facts block, and publish date on the next re-sync.

For WhatsApp, configure the phone number ID, access token, app secret, business account ID, and generated webhook verify token. Use the connector detail's `webhookUrl` as the Meta webhook callback URL. Radioso verifies `X-Hub-Signature-256`, ignores duplicate message IDs, and stores message logs for retry and recovery.

WhatsApp text messages are sent through assistant chat. Non-text WhatsApp messages are not converted into assistant user turns. If you configure an unsupported-message reply, Radioso sends that exact reply through WhatsApp; otherwise those messages are recorded as skipped.

## Save connector config

Use:

```text
PUT /api/v1/connectors/{connectorId}
```

Then enable it with:

```text
POST /api/v1/connectors/{connectorId}/enable
```

Disable it with:

```text
POST /api/v1/connectors/{connectorId}/disable
```

## Run a manual sync

Use:

```text
POST /api/v1/connectors/{connectorId}/sync
```

The response returns `202` when the sync has been accepted:

```json
{
  "accepted": true
}
```

The sync continues after the HTTP request returns. Re-read the connector detail to see updated `syncState`. Not every connector supports manual sync. Unsupported or already-running syncs return `409`.

For WordPress, the connector creates its source record before it calls the WordPress REST API. This keeps failed syncs visible under **Knowledge → Sources**, including failures that happen before WordPress returns the first post.

A workspace WordPress connector accepts one configured site. Companion-plugin webhooks include a signed site URL, and Radioso rejects events when that URL or the post permalink does not belong to the configured site. Changing the WordPress site URL rotates the generated webhook secret; copy the new secret into the plugin settings for the new site.

## Endpoint reference

```text
GET  /api/v1/connectors
GET  /api/v1/connectors/{connectorId}
PUT  /api/v1/connectors/{connectorId}
POST /api/v1/connectors/{connectorId}/enable
POST /api/v1/connectors/{connectorId}/disable
POST /api/v1/connectors/{connectorId}/sync
```

## Common failure modes

- `400` usually means the connector config is incomplete or invalid.
- `401` means the authenticated workspace context is missing for connector-management routes.
- `404` means the connector or workspace was not found.
- `409` usually means the connector is in a conflicting state for the requested save or enable action, does not support manual sync, or already has a sync running.
