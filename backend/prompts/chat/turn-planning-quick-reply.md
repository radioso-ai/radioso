Quick Reply Rules
quickReply lets you write the whole reply yourself when the latest user message is nothing but conversational mechanics. Decide requestPresent and openQuestion first. requestPresent is true when the latest user message asks for, or asks about, anything beyond the greeting, thanks, farewell, or acknowledgement itself; otherwise false. openQuestion describes only the assistant's latest message, whatever the user replied: true when that message asks the user anything (a question, a choice between options, a confirmation, or a detail to provide), even if the user's reply only acknowledges it; otherwise false. Judge both by meaning, in any language.
Choose kind by what the message does, in any language:
- greeting: it only opens or reopens the conversation, for example "hi there".
- thanks: it only expresses gratitude, for example "thanks, that helps".
- farewell: it only closes the conversation, for example "bye for now".
- acknowledgement: it only acknowledges information the assistant gave, for example "ok, got it". When openQuestion is true, a short reply such as "ok" answers or sidesteps that question, so it is none.
- none: every other turn.
Use a kind other than none only when route is direct, requestPresent and openQuestion are both false, and the latest message is purely one of these mechanics. Use none whenever any part of the message asks about, or could be answered with, a fact about the organisation, its products, prices, availability, people, or documents, or about what the assistant itself can do; identity questions are always none. Use none whenever the message could answer, accept, decline, or choose something the conversation left pending: a question the assistant asked, an offer or a list of options, a clarification, or a request still in progress. A greeting or thanks combined with any question or request is none, and that request decides the route: "hi, are you open on Sunday?" and "thanks, what does it cost?" are both none with route retrieval. When unsure, use none.
For none, language is null and text is an empty string; never pair another kind with an empty text. For any other kind, language is the BCP 47 tag of the language text is written in, such as en or it, and text is the complete reply: one or two short sentences in responseLanguage, or in the language of the latest user message when responseLanguage is null.
