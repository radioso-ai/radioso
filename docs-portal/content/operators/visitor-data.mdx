# Visitor data

A conversation records a handful of facts about the visit that started it, so operators can triage abuse, see where traffic comes from, and recognize a returning visitor. This page lists every one of those fields, where it's visible, and what happens to it.

## What gets recorded

Radioso records these once, when a conversation starts, and never overwrites them for that conversation:

- **IP address** — the address the request came from, resolved from the trusted end of the forwarded-for chain.
- **Country, region, city** — read from a geo header the deployment's load balancer or CDN supplies, when one is present.
- **Browser user agent** — the raw `User-Agent` header.
- **Browser language** — the raw `Accept-Language` header, plus the primary tag Radioso derives from it (`de-DE,de;q=0.9` becomes `de`).
- **Entry page** — the page the chat opened on.
- **Referrer** — the page that sent the visitor there.

A durable visitor key — generated by the embed launcher and stored in the host page's `localStorage` — links these facts, and every conversation the same browser starts, into one visitor record. See [what the widget records](/quickstarts/website-embed#what-the-widget-records). A host-verified customer id from [signed visitor identity](/operators/context-variables#signed-visitor-identity) links conversations the same way and takes over once it appears, ahead of the visitor key.

## Where it's visible

Every field above shows up for operators in the Inbox conversation drawer's Visitor panel — see [Operator console](/operators/human-takeover#operator-console). The same fields, including the IP address, are available through the history API to a signed-in workspace session or an eligible personal or service-account credential — see [Conversation history](/api/chat-and-history#conversation-history).

None of it reaches the model, a prompt, or a stored trace except the six fields behind the `visitor_request` context variable — country, region, city, language, referrer, and entry page — and even those never carry the IP address or the raw user agent. See [Visitor request](/operators/context-variables#visitor-request).

## Retention

These fields live as long as the conversation that recorded them. There is no conversation-delete endpoint today, so nothing removes them on its own before that; deleting a workspace deletes every conversation, and every visitor record, that belongs to it.
