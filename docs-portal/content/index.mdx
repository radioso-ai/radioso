# Radioso for teams that need answers they can defend

Radioso is built for teams that need grounded answers, traceable citations, and embedded support experiences. The goal of this site is simple: help you reach a real first success, then explain the system well enough that you can trust it in production.

<Callout type="info" emoji="↗">
  Choose one path first: evaluate locally, integrate through the API, or launch the website embed.
</Callout>

## Choose your path

<Cards num={3}>
  <Cards.Card title="Evaluate locally" href="/quickstarts/run-locally">
    Bring up the full stack with Docker, create or join a workspace, upload a document, and verify one grounded answer in your own environment.
  </Cards.Card>
  <Cards.Card title="Launch the website embed" href="/quickstarts/website-embed">
    Configure allowed origins, enable the embed launcher, verify session bootstrap, and test both approved and blocked origins before rollout.
  </Cards.Card>
  <Cards.Card title="Integrate API-first" href="/quickstarts/api-first-success">
    Create an account, reveal a workspace token, upload content, and ask a question with plain HTTP or the TypeScript SDK.
  </Cards.Card>
</Cards>

## What success looks like

<Steps>
### Reach a visible result

Do not stop at setup. Upload one real document, ask one real question, or load one real embedded launcher.

### Check the evidence

The answer should be grounded, the citations should be traceable, and the widget or API flow should behave the way the docs say it behaves.

### Understand the system

Use the architecture and operator guides to understand how retrieval, document processing, and deployment fit together.
</Steps>
