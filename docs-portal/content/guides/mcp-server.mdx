# MCP server

Radioso exposes MCP surfaces for workspace document work and for talking to one agent. The surfaces have different scopes and credentials. This page covers a self-hosted MCP deployment and the client setup that the current credential model supports.

## Two surfaces, two boundaries

- **Workspace document tools** are retrieval-first tools such as `list_documents`, `get_document`, `search_documents`, and `answer_grounded`. They are scoped to a whole workspace. Personal tokens and service-account credentials are currently rejected by these MCP tools, so do not paste a REST API credential into an MCP configuration.
- **Agent converse** binds a client to one agent's persona, directives, routines, history, and retrieval settings. A workspace administrator creates its per-agent converse grant from the signed-in dashboard. The client then exchanges that grant for a short-lived converse session.

The dashboard session is the management boundary. It creates and revokes converse grants and manages workspace settings; API credentials do not mint grants or reveal secrets.

## Enable it

<Steps>
### Choose a deployment shape

Run MCP merged into the backend, or run `packages/radioso-mcp-server` as a standalone process. In merged mode set `RADIOSO_MCP_ENABLED=true` and leave `RADIOSO_MCP_STANDALONE=false`. MCP mounts at `RADIOSO_MCP_MOUNT_PATH` (default `/mcp`) on the backend origin.

Standalone mode needs `RADIOSO_BASE_URL` pointed at the backend and an explicit `RADIOSO_MCP_SIGNING_SECRET` shared by the MCP process and backend. Set `RADIOSO_MCP_REDIS_URL` on both processes when they need shared session state.

### Confirm the backend connection

Standalone mode needs a reachable backend for agent-converse requests. The workspace MCP context endpoint is a dashboard-session endpoint, not a standalone credential exchange.

### Create the supported grant

Sign in to the dashboard, open the agent's **Channels → MCP** settings, and create a converse grant there. Copy the one-time grant secret into the secure configuration of the client or connector that will exchange it. The grant secret is not shown again.
</Steps>

<Callout type="info" emoji="i">
  Workspace document MCP currently rejects personal and service API credentials. Agent converse grants are created by a signed-in workspace administrator; they are not created with an API bearer header.
</Callout>

## Agent converse setup

The dashboard grant is bound to one agent. The MCP client exchanges the grant with the configured MCP server and receives a short-lived session token. Keep both the grant and the returned session token in the client or connector's secret store. Revoke the grant from the dashboard when the client should lose access; the server re-checks grant state for every request.

The converse surface provides:

- **`ask_agent`** — sends a message through the agent's full turn loop and continues its conversation.
- **`answer_grounded`** — returns a grounded answer using the bound agent's retrieval settings without creating a conversational turn.
- **Agent documents as resources** — lists and reads documents the bound agent can see.

The converse session does not grant access to other agents, workspace administration, account management, API-access settings, connector secrets, or provider keys.

## Workspace document tools

Workspace document tools are not available through MCP credential setup. A personal token or service-account credential sent as `Authorization: Bearer ...` is rejected. Use the dashboard or the REST document routes for workspace document work.

## Deployment notes

Same-host merged mode is convenient for a local self-hosted client because the MCP URL uses the backend origin. Standalone mode is useful when the MCP process needs separate public HTTPS exposure. Hosted remote clients such as Claude or ChatGPT need a public HTTPS URL; a localhost URL is reachable only from a client running on the same machine.

The MCP server's deployment signing secret authenticates traffic between a standalone MCP process and the backend. It is different from API credentials, converse grants, public-chat launch values, provider keys, and connector secrets.

## Authentication boundaries

- Workspace document tools reject personal and service API credentials.
- Agent converse grants are created and revoked through the signed-in dashboard session.
- Agent converse requests accept only a valid converse session created from an active grant.
- Public-chat launch values and website-embed values cannot be reused for MCP converse.
- MCP does not reveal REST, provider, connector, public-launch, or signing-key secrets.

## Common failure modes

- **A workspace document tool returns `401`.** The workspace MCP surface does not accept the supplied personal or service credential. Use the dashboard or an eligible REST route.
- **The converse client cannot connect.** Confirm the MCP URL is reachable over HTTPS for hosted clients, and check `RADIOSO_BASE_URL` and `RADIOSO_MCP_SIGNING_SECRET` in standalone mode.
- **A converse session is rejected.** The grant may be revoked, expired, disabled, or issued for a different agent. Create or revoke grants from the agent's MCP settings with a current dashboard session.
- **A write tool waits in the client UI.** The MCP host is honoring `requiresApproval: true`; approve the operation in that host.
